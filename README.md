# SSG Playground — Chapter 10: Use Hugo Templates to Display Your Content

Welcome to the hands-on playground repository for **Chapter 10** of *Static Site Generators in the Age of AI*.

This branch (`chapter-10`) is **additive from `chapter-09`**. It activates the metadata created in Chapter 9 by using Hugo's built-in Go templating engine to conditionally render descriptions, statuses, and tools on project pages, and to automatically generate the Projects section listing.

## Part of the Open-Source Book

This playground is part of the open-source book **Static Site Generators in the Age of AI**. The original book is available at [polla-fattah/ssg-book](https://github.com/polla-fattah/ssg-book).

---

## 🎯 Chapter 10 Goals

- **Template Expressions**: Read and use Hugo page methods (`.Title`, `.Description`, `.Content`, `.RelPermalink`) and custom parameters (`.Params.status`, `.Params.tools`).
- **Understanding Context (The Dot `.`)**: Track what `.` represents as execution moves into and out of template blocks.
- **Conditional Rendering (`if` and `with`)**: Display content only when values are provided, ensuring missing fields do not leave empty HTML tags (such as `<p></p>`) behind.
- **Repeating Markup (`range`)**: Iterate over lists of strings (project tools) and collections of pages (`.RegularPages.ByTitle`).
- **Automating Section Listings**: Replace the manually maintained project links in `content/projects/_index.md` with an automatic, sorted list generated by Hugo.
- **Diagnosing Context Errors**: Identify and resolve common template mistakes (e.g. evaluating a page property like `.Title` when the dot has shifted to a string).

## 🔍 The Template Implementation (`layouts/all.html`)

Inside the `<article>` element of `layouts/all.html`, the layout now displays page metadata conditionally and dynamically builds the section list:

```html
<article>
  <h1>{{ .Title }}</h1>

  {{ with .Description }}
    <p>{{ . }}</p>
  {{ end }}

  {{ with .Params.status }}
    <p><strong>Status:</strong> {{ . }}</p>
  {{ end }}

  {{ with .Params.tools }}
    <p><strong>Tools:</strong></p>
    <ul>
      {{ range . }}
        <li>{{ . }}</li>
      {{ end }}
    </ul>
  {{ end }}

  {{ .Content }}

  {{ if and .IsSection (eq .Section "projects") }}
    <h2>Current work</h2>
    <ul>
      {{ range .RegularPages.ByTitle }}
        <li>
          <a href="{{ .RelPermalink }}">{{ .Title }}</a>
          {{ with .Description }}
            <p>{{ . }}</p>
          {{ end }}
          {{ with .Params.status }}
            <p><strong>Status:</strong> {{ . }}</p>
          {{ end }}
        </li>
      {{ else }}
        <li>No projects to display yet.</li>
      {{ end }}
    </ul>
  {{ end }}
</article>
```

---

## 🧠 Following the Dot (`.`)

| Expression / Position | What `.` Represents |
|---|---|
| Page level (outside any block) | The current Page object |
| Inside `{{ with .Description }}` | The description string (print with `{{ . }}`) |
| Inside `{{ with .Params.status }}` | The status string (e.g. `"in-progress"`) |
| Inside `{{ with .Params.tools }}` | The slice/list of tools |
| Inside `{{ range . }}` (tools) | A single tool string (e.g. `"Hugo"`) |
| Inside `{{ range .RegularPages.ByTitle }}` | A project Page object from the collection |
| Inside `with .Description` inside `range` | The project's description string |

## 🧪 Automated Testing

Run the automated test suite across all chapters:

```bash
# Run Chapter 10 specific tests:
python -m unittest tests/test_chapter_10.py

# Run all tests across Chapters 1 through 10:
python -m unittest discover tests
```

### Test Coverage in `test_chapter_10.py`:
1. `test_hugo_build_clean`: Verifies clean Hugo build with zero warnings or errors.
2. `test_layouts_all_structure`: Verifies `with`, `range`, `.IsSection`, `.RegularPages.ByTitle`, and `.RelPermalink` in `layouts/all.html`.
3. `test_projects_index_markdown_cleaned`: Confirms manual bullets and headings were removed from `content/projects/_index.md`.
4. `test_rendered_project_pages_contain_metadata`: Confirms descriptions, statuses, and tools are rendered into HTML for both projects.
5. `test_rendered_projects_section_list`: Confirms `/my-knowledge-site/projects/` generates the sorted list of projects with correct links and statuses.
6. `test_non_project_pages_omit_project_metadata`: Ensures standard pages (like About) do not render empty status or tools tags.
